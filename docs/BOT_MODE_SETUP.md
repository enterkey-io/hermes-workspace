# Prepare native Bot Mode during agent installation

This step runs on the owner's existing Hermes, independently of web hosting. A working bridge with zero managed bots is not a usable Bot Mode installation. Ordinary Hermes agent profiles are not automatically managed Bot Mode bots. The installer must check readiness before handing the owner a connection address.

The owner does not need Hermes Desktop or its Bots tab to complete this step. Their Hermes agent can perform the local native operations below. “Bot creation is not implemented in the browser app” does not mean agent-side native setup is unavailable or should be postponed.

## Reuse first; create only within the owner's request

Use the exact executable, runtime, Hermes home and profile context intended for the bridge service. Query native `profiles.list` with `include_sessions: true`. Managed bots have a `ui_meta["hermes-bots"]` object; initialized chats have `canonical_session.id`. Report counts and readiness without publishing profile names, history or private configuration. If bots exist elsewhere, fix the service's home/profile context rather than creating replacements in an empty home.

Reuse existing managed bots and their native canonical chats. Do not turn every ordinary profile into a managed bot, rename or retire existing chats, or write a substitute roster/database. If the owner's installation request includes creating a starter bot when none exist (as the app's setup message now does), create one minimally configured bot using their current model/provider settings. No new model subscription, provider key, scheduled job or external channel is required. If creating a bot is outside their request, obtain that choice before changing profiles; report the installation as awaiting Bot Mode setup.

## Native setup contract for the tested builds

An agent can use Hermes Desktop's native bot setup, or perform the same native operations locally through Hermes's JSON-RPC stdio gateway (`python -m tui_gateway.entry`, in the existing Hermes interpreter/home context). Read responses by request id; native events may interleave. These are **local operator setup operations**, not additional operations exposed by the web bridge. Keep credentials and raw private responses local. Do not patch core files or directly edit the session database.

1. Read `profiles.list` with `{"include_sessions":true}` and confirm the intended home. Do not treat an RPC error as an empty list.
2. Only if a new starter bot is authorized and no managed bot exists, choose an unused profile name and call `profiles.create` with that name and `no_alias: true`. The tested native create handler normally inherits launch model/provider credentials locally; verify the result and the intended profile's configuration without printing secrets. Preserve the owner's settings and channel separation; do not clone external channel tokens. If inheritance is unavailable or incomplete, report the missing setup rather than claiming a usable bot.
3. Mark **that new profile** as a managed bot using `profiles.configure` with `name` and `ui_meta: {"hermes-bots":{"title":"Assistant"}}`. Verify `applied.ui_meta` is true. For existing bots, preserve their metadata; do not replace it. These builds report `bot_mode_protocol: true` and inject their native teammate protocol; do not append a second protocol to SOUL.md.
4. For an existing canonical chat, reuse the server's canonical identity and compression lineage. If initialization is needed, first call `session.list` with `{"profile":"<chosen-profile>","title":"Bot Chat","include_hidden":true,"limit":100}`. Adopt an existing native Bot Chat instead of creating another. Stop on lookup failure or disagreement with a previously reported canonical identity. Never resurrect a deliberately retired chat without the owner's direction.
5. For a confirmed first-ever Bot Chat only, call `session.create` with `{"profile":"<chosen-profile>","title":"Bot Chat","hidden":true,"follow_profile_config":true}`. Use its returned runtime `session_id` in `session.title` with `{"session_id":"<returned-runtime-id>","title":"Bot Chat"}`. This native title operation materializes the canonical row without a model prompt. Do not fabricate session ids or insert database rows. If another writer wins the canonical identity, re-read and adopt that identity; do not mint more chats or force a rename.
6. Re-read `profiles.list` and confirm that the chosen managed bot has `canonical_session.id`. Repeating the install must reuse it. Verify the bridge's authenticated `bots.list` reports the same ready bot; if it does not, investigate home/profile context or metadata instead of retrying creation. Do not print the operator credential in commands, logs or replies.

This is based on the tested native handlers and Desktop Bot Mode's creation flow at revisions `29112bef` and `af0cd4df`. Source references for af0cd4df: [profile handlers](https://github.com/enterkey-io/hermes-agent/blob/af0cd4df34c73e41bcfcfa46c4081d1d83bdc81a/tui_gateway/methods_profiles.py), [session handlers](https://github.com/enterkey-io/hermes-agent/blob/af0cd4df34c73e41bcfcfa46c4081d1d83bdc81a/tui_gateway/methods_session.py), and [Desktop canonical chat initialization](https://github.com/enterkey-io/hermes-agent/blob/af0cd4df34c73e41bcfcfa46c4081d1d83bdc81a/apps/desktop/src/plugins/hermes-bots/canonical-chat.ts). This is version-specific guidance, not permission to enable unknown adapter builds.

## Finish the connection test

Verify the authenticated event stream as well as the lists: `/v1/events` must return 200 with `application/x-ndjson`, emit `bridge.ready` immediately, and then keep sending heartbeat frames at roughly 15-second intervals. Use the exact allowed app Origin, an authorized credential in the Authorization header, and the connection lease in X-Bot-Connection. Compare the container loopback path with the real HTTPS URL if streaming fails. Inspect only status, media type and control frames for this diagnosis; keep credentials and bot content out of reports. A successful preflight or pairing request does not prove streaming works. Preserve TLS trust and origin/Host checks; do not move credentials into URLs or weaken authentication to troubleshoot.

Watch for at least 50 seconds, including when no bot session is open. A 200 response followed by an open but silent socket is a failed liveness check: the web client times out after 35 seconds without data. Plugin 0.2.1 could starve heartbeats when unrelated native events kept its queue busy but were filtered out of the browser's session scope. Plugin 0.2.3 schedules heartbeats independently of those events. Missing heartbeats on both loopback and HTTPS must be investigated on the bridge/runtime side before blaming the tunnel or an earlier outage. Do not disable the browser's idle deadline or relax session filtering to hide the problem.

## Clean up probes without disconnecting the owner

Keep each diagnostic probe's connection lease private. In a `finally` block, close its stream/HTTP reader and send authenticated **DELETE `/v1/connect`** using that probe's own X-Bot-Connection, Origin and credential. An operator probe must close its own operator lease. This frees a slot without revoking unrelated browser grants; retain their TLS/Host/origin protections. If a probe failed before obtaining a lease, close its transport only. Avoid parallel unnecessary probes that exhaust the eight-connection limit.

**Do not use `hermes bot-web revoke` or POST `/v1/pairing/revoke` as probe cleanup.** They invalidate all browser grants and leases, even if `--app-origin` is supplied. Use global revocation only for an owner-requested all-device sign-out or access response. If it was run accidentally, tell the owner that their grant was invalidated and that fresh pairing is required; a browser error afterward does not prove a broken tunnel. If unknown stale probes fill all slots, stop and report that specific issue instead of silently clearing the owner's access.

Once the owner pairs, they can select **Refresh bots** after agent-side setup; another installation is not necessary. Report infrastructure checks, Bot Mode readiness, owner browser pairing/roster, live stream and restart durability separately. Do not send model prompts or execute tools just to initialize or verify setup.
