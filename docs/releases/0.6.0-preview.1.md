# Pebble Crew 0.6.0 preview

The shared design system now covers chat, Settings, Account, Connections,
Requests, onboarding, New/Edit pebble and Crew dialogs. Forms use the same
surfaces, type, focus treatment, tabs, spacing and motion as the conversation.

- Tool activity is grouped; empty timestamp-only bubbles and hidden reasoning
  no longer appear as messages. Real replies, final-answer sidecars, native IDs,
  approvals and meaningful tool results remain available.
- Avatars rest looking up/right, breathe gently, follow the pointer smoothly
  over their row/details and return to rest after a completion. The app and lab
  share one visibility-aware scheduler; reduced motion stays static.
- Centered pins, attached Main Pebble stars, genuine role chips, transparent
  collision-aware action menus and an owner avatar menu. Pin changes respond
  immediately, show pending state, animate and reconcile or roll back.
- Create Crews from the sidebar + menu. Crews organize pebbles; Group chats are
  separate native conversations. Removing a Crew preserves profiles, chats and
  reporting. New/Edit pebble has focused forms, scoped saves, dirty-navigation
  protection and explicit resolution of conflicting saved edits. Retired
  identities cannot silently redirect an editor to a replacement profile.
- Details can open/close at every screen size. Routines and Files use tabs;
  idle Ready text is gone. Hover, drawers, pin moves and Latest messages have
  bounded motion, with reduced-motion alternatives and keyboard focus handling.
- Real file pick/paste/drop, upload, attachment-only send and authenticated
  download on the owner's host. Limits are 5 files, 10 MiB each, 25 MiB/send.
  Files stay bound to the native profile incarnation and canonical conversation.
  Durable receipts prevent automatic replay after an uncertain send. Files lists
  inputs shared through Pebble Crew; automatic indexing of old/native-generated
  output files is not included. Group-chat file delivery is not enabled.
- Experimental native Computer prototype (disabled by default) on the supported
  0.21.7 Linux host: lazy viewer,
  explicit start/stop, Watch/Take control/Hand back and native lease enforcement.
  It uses short-lived, single-use tickets through an authenticated fixed route;
  no general VNC port or dashboard proxy is exposed. Each profile's screen
  shares the host security boundary, not an isolated OS. Desktop dependencies
  are never installed silently. The real native ticket/RFB/control transport
  passed a synthetic framebuffer probe; Linux Xvnc launch/device behavior is
  still a host acceptance gate. It stays out of ordinary navigation until that
  gate passes. Operator-only test opt-in is
  `HERMES_BOT_WEB_EXPERIMENTAL_COMPUTER=1`; unsupported hosts/builds still omit
  the tab.

Validation uses synthetic content and disposable native homes on exact revisions
29112bef (0.21.0) and af0cd4df (0.21.7). See the
[verification report](../compatibility/preview-0.6.0-local.json). Automated checks
are not formal accessibility certification. This remains a development preview.

## Existing installation

Give the installing Hermes agent this
[tagged update guide](https://github.com/enterkey-io/pebble-crew/blob/v0.6.0-preview.1/docs/AGENT_INSTALL.md#updates-and-rollback).
Update the combined plugin; preserve the owner login, native profiles, SOUL,
memories, tools, role/crew metadata, avatars, history, HTTPS address, ports and
supervisor. Do not create a new login, repeat pairing/onboarding, create starter
bots or run a paid-model installation probe. Verify the existing HTTPS route
and restart supervision. Reopen that same app URL to load the new interface.

Publishing this package does not upgrade the owner's remote Hermes host.
