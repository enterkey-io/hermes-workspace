# Pebble Crew 0.5.0 preview

The native Bot Mode interface now has a sectioned chat rail, larger pinned
pebbles, legible lead badges, role chips, native previews, crew avatar stacks,
readable message bubbles with actual times/authors, and a compact composer.
Selected-agent details and routine controls move into accessible drawers on
smaller screens. Existing animated avatars and owner photos remain supported.

- Agent changes reconcile immediately after app actions and automatically across
  browsers and outside Hermes changes. No manual roster refresh is needed.
- Native pins, ordering, read state, Hide/Unhide and bot-owned routine controls.
  Per-conversation drafts and reading position survive switching and reconnect.
- Real native Delete, available as an owner action or an agent proposal. Exact
  profile identity and typed owner confirmation are required. Models cannot
  approve their own requests. Default/lead agents, direct reports, active work
  and live crew membership are protected.
- Stable profile incarnations prevent recreated names or clones from inheriting
  drafts, handles, open-session permissions or destructive approvals. Proven
  native renames retain identity. Optional local presentation tables support
  code rollback without resetting login or native history.
- Shared production components/tokens, populated desktop/tablet/phone tests,
  reduced-motion checks and expanded native lifecycle/security tests.

This remains a development preview. Hermes 0.21.7 can remove profile files while
reporting identity settlement pending; Pebble Crew keeps that partial receipt
and offers inspection, with no automatic destructive retry. Both supported
native builds freeze crew membership, so retire a live crew in Hermes before
deleting one of its members. Hide remains immediately available.

Validation uses synthetic data, disposable Hermes homes and a local model on
native revisions 29112bef (0.21.0) and af0cd4df (0.21.7). See the
[verification report](../compatibility/preview-0.5.0-local.json). Owner-host Linux
boot, container replacement and actual remote routes need installation-specific
verification; the developer did not upgrade an owner's running host.

For an existing installation, give its Hermes agent the
[tagged update guide](https://github.com/enterkey-io/pebble-crew/blob/v0.5.0-preview.1/docs/AGENT_INSTALL.md#updates-and-rollback).
Preserve the owner login, primary agent, existing HTTPS address, ports, keys,
profiles, roles, avatars and history. Do not create another login or repeat
pairing/onboarding. Verify the route, then reopen the same app URL once to load
the new interface. Installation verification must not create/delete bots or
send paid-model prompts.
